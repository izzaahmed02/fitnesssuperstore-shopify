## Why `sale_price > 0` cannot be the selector

Confirmed in the generated 861-row French Fitness file: all 16 approved products
are present with prices matching Shopify, `promotion_id` and `sale_price` are
blank on all 16, and 44 unrelated rows do carry `sale_price`. The discount is an
automatic cart-level benefit, so it never lands in a per-item `sale_price` — that
is the correct behaviour, and it is why the campaign needs an explicit marker.

Do not manufacture `sale_price` values to create a selector. That would both
misstate the offer to Google and risk a second discount path.

## Where the marker belongs — not this repo, not the theme

The primary feeds are generated by the Multifeeds app, so the marker is a feed

the theme-sync branch or PR #833. This directory holds evidence and the exact
target values only.

## Reason-coded ID diff

`september_overstock_16_id_diff.csv`.

The feed `id` field is not a per-row mapping. It is the gated rollout expression
in Multifeeds (feed → Basic → Item ID):

```
if   metafield(custom.gmc_id_rollout_status) == "approved"
 and metafield(custom.legacy_gmc_id) != ""
then metafield(custom.legacy_gmc_id)
else Product ID
```

This is the same gate behind the 114 numeric-id rows in the separate offer-ID
correction thread. Applied to the 16 September products as they stand today:

| Reason code | Rows | Meaning |
| --- | --- | --- |
| `GATE_PASS_LEGACY_EQ_SKU` | 16 | rollout `approved`, `legacy_gmc_id` populated and identical to the variant SKU, so the feed emits the SKU |
| `GATE_FALLTHROUGH_NUMERIC` | 0 | rollout not approved or `legacy_gmc_id` empty — emits the numeric product ID |
| `LEGACY_NE_SKU` | 0 | gate passes but `legacy_gmc_id` differs from the SKU |
| `COMPOSITE_MULTIVARIANT` | 0 | multi-variant product keyed `<product ID>-<variant ID>` |
| `SKU_MISSING` | 0 | no SKU to key on |

**Result: zero diff on all 16.** Every September product already emits its
SKU-keyed id, none falls through to a numeric product ID, none is a composite
row, and none collides. So the marker can be keyed on these 16 ids without any
identity flip, and without the performance-history reset an id change would cost.

One gate remains before this is treated as final: the processed Merchant Center
item IDs have not been read independently here. Shopify-side values only.
