## 0. Correction to the 5 October live-search figures — READ FIRST
The result counts and rankings in my 5 October note, and in section 4 of
`Boost_Change_Packet_2026-10-05.md`, were **Shopify's native storefront search, not Boost**.

Why the mistake happened: I read the `search_submitted` web-pixels payload and the
`<title>` ("Search: 110 results found for ...") off `/search?q=`. Both are produced by
Shopify's own storefront renderer. Boost's result grid on that page is a client-side
placeholder (`<!-- TEMPLATE PRODUCT LIST PLACEHOLDER -->`) filled from
`services.mybcapps.com`, which is blocked from this environment by network policy.
So the engine I measured was not the engine customers see.

**Retracted — do not rely on these, they were never Boost numbers:**
- "45 kettlebell now returns both 45 lb kettlebells first"
- "bumper plate 45-pound now returns the correct plates"
- "assault bike now returns 6 results"
- The whole result-count table (rubber hex dumbbell 380, bumper plate 45 lbs 178, etc.)

One of those is now positively contradicted: **no product in the catalog matches "assault" at all** on the fields Shopify's admin
product search covers, which are title, SKU, vendor, type and tags (checked 8 Oct). Andrew's original finding that "assault bike" returns
nothing in Boost has not been shown to be fixed.

**Unaffected and still verified** (these came from the Shopify Admin API, not from search):
- Product Type carries no class data (see §1).
- Description noise: the Urethane 8 Sided Hex Dumbbell copy contains "traditional rubber
  dumbbells", and each description carries a cross-link table naming every sibling weight.
- At least 136 active products use an "lb" title form with no "lbs" anywhere.

The real before-state for GO 2 therefore still needs to be captured, from a browser where
Boost actually loads. §3 is how.

## 3. Capture method — run this from your own browser
Boost results cannot be read from this environment. Run the capture yourself, in a
logged-out Incognito window on a US connection, matching the accepted method
(no filters, relevance sort, page 1).

1. Open an Incognito window, US VPN on, go to `https://www.fitnesssuperstore.com/`.
2. Open DevTools (F12) -> Console.
3. Paste the script in `go2-capture.js` (next to this file) and press Enter.
4. It prompts for a label. Use `PRE-TOGGLE-ON`, then `POST-TOGGLE-OFF`, then
   `POST-REVERT-ON`. It copies the JSON to your clipboard; paste each into a file.

If the script is blocked for any reason, fall back to capturing by hand: search each of
the 19 queries, record the result count Boost shows and the first ten product titles.

## 4. Execution order
1. **Record the before-state.** In Boost admin, screenshot and write down the current
   values of Search Personalization, Product Performance Ranking, Semantic Search impact
   weight, and the searchable-field priorities. This is the rollback reference.
2. **PRE-TOGGLE-ON capture.** Run §3. Note the exact UTC time.
3. **Toggle.** Boost admin -> Search -> AI Search: set Search Personalization OFF and
   Product Performance Ranking OFF. Save. Record the exact toggle timestamp.
4. **Sync.** Trigger a Manual sync and wait for it to report finished. Boost confirmed on
   4 Oct there is no preview and no staging; the change is live once sync completes.
5. **POST-TOGGLE-OFF capture.** Run §3 again immediately. Note the exact UTC time.
6. **Revert.** Turn both settings back ON, save, sync. Record the revert timestamp.
7. **POST-REVERT-ON capture.** Run §3 a third time to prove the revert restored the
   prior state.

## 5. Stop conditions
Roll back the same day, before step 6's scheduled time, if any of these appear in the
POST-TOGGLE-OFF capture:
- An exact-name query stops returning its named product in the top three. The three that
  matter: French Fitness Rubber Coated Hex Dumbbells, French Fitness FFS Silver Dual
  Adjustable Pulley, fsr100.
- Any tracked query errors or returns nothing.
- A hidden, archived or test product appears.

Per Tim's 23 September ruling, rank movement on its own is observational, not a
regression. Judge on relevance, not on raw counts.

## 6. What to report back as PASS or HOLD
- Exact toggle and revert timestamps.
- Before and after results for all 19 queries.
- What clearly improved.
- What clearly worsened.
- Whether the three control searches regressed.

## 7. What comes after, and in what order
Tim approved these as separate, sequential tests. Do not combine them.
- **A. Description searchable field OFF.** Approved as the next isolated test once GO 2 is
  closed. Keep the description content itself; only remove Description from the searchable
  fields.
- **B. Semantic Search.** After A is measured. Boost confirmed it sits at a 50% impact
  weight and is the only mechanism that admits products with no keyword match. Reducing
  it to 0 is the cleanest supported test, because it isolates the behaviour rather than
  producing a partial effect that cannot be attributed. Send Tim the exact setting,
  expected effect and rollback immediately before executing.
