## 4. Answer: it is Product Category, not Product Type
Verified against the Shopify Admin API on 12 Oct.

**Product Type is unusable**, unchanged from the earlier finding: of 3,755 active products,
3,735 carry the single value "Product Index", 17 are "Product (Hidden)", 3 are blank.

**Product Category is populated with real equipment class.** Exact figures from the Shopify
Admin API, 12 Oct, all active products:

| | Active products |
|---|---|
| Carry a real taxonomy category | 3,615 (96.3%) |
| Uncategorized | 140 (3.7%) |
| **Total active** | **3,755** |

140 + 3,615 reconciles to 3,755. Spread across classes is genuine, for example Weight Lifting
Machines with Pulleys 687, Elliptical Trainers 317, Treadmills 246, Exercise Benches 196,
Dumbbells 181, Smith Machines 34.

**What the 140 Uncategorized are.** Sampled 30 of them: almost entirely accessories and small
items, not machines. Head harnesses, yoga mats, landmine attachments, lifting belts, barbell
pads, Olympic sleeve adapters, plyo boxes, push-up bars, Power Plate shields and T-bar row
platforms. So the class signal is strongest exactly where it matters most, on the machines,
and the gap sits on accessories.

That gap is worth naming rather than waving through. Andrew's Tier 2 requires that a class
query must not admit an accessory to that class. Accessories with no category carry no class
signal at all, so weighting Product Category to Medium will not by itself stop accessory
leakage into machine queries. It should still be measured, not assumed.

Tags were considered and rejected as the class field. They are heavily overloaded: one
product in the sample carried 23 tags mixing class, brand, product line and the URL handle.
Raising Tags to Medium would import that noise into ranking.

**So Boost's revised recommendation is workable if "the field containing product class" is
read as Product Category.** Product Type should stay where it is or go to Low, since it
carries no signal.
